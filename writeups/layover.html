Layover

A Linux Medium box that hands you a single contractor login and then quietly lets that contractor become root on the WiFi workstation. From there it is a monitor-mode sniff for Jenny's credentials, a Craft CMS SSTI for the first shell, and a CUPS token-coercion privesc all the way to root.

Medium Linux Author · TRX

Craft CMS 5.9.8 RCE

Jenny's creds get you into Craft CMS, and now the version is right there in your face: Craft CMS 5.9.8.

That version is vulnerable — pick your CVE. The one I used is CVE-2026-31857: Remote Code Execution via Relational Conditionals:

Unsanitized user input reaches the unsandboxed renderObjectTemplate() function, triggering template injection and code execution via element listing endpoints.

It's basically SSTI with extra steps. And while hunting for a PoC, I found TRX-0/CVE-2026-31857-craftcms-ssti — which I'm 90% sure belongs to the author of this box. Small world. Thanks for the exploit, TRX.

🔴 Fun fact: my very first RCE shell landed on… my own attacker machine. The victim couldn't reach my IP, so I helpfully reverse-shelled myself. Not my proudest moment, but hey — it worked, just on the wrong machine.

After that little detour, we did get a real shell:

Takeaways

GG, Layover. Cloning wlan2 into mon2 is still my favorite part of this one — instead of using the empty wlan3 that was just sitting there, we built our own monitor interface from scratch.

The chain itself is a good reminder that "internal" is not the same as "trusted": a workstation password reused for sudo, cleartext WiFi traffic, secrets living in .env, and a localhost-only printing service were enough to go from a contractor login to root.
